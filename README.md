# 序时 · 科研与求职工作台

真实可启动的中文个人工作台，初始化 **2026-10-11—2026-10-31 / Asia/Shanghai**。包含今日、周计划、项目与成果、复盘、设置与记录五个视图。所有编辑保存到服务端，而非静态演示。

## 启动

需要 **Node.js 24 或更新版本**（使用内置 `node:sqlite`，无生产第三方依赖）。

```bash
cd /workspace/worktable
npm ci --ignore-scripts --no-audit --no-fund
npm start
```

默认监听本机 `127.0.0.1:3000`。在运行服务器的电脑上用浏览器访问端口3000。点击“首次使用，创建账户”，用户名至少2字符，密码至少10字符。首次本机注册后，默认关闭后续注册。没有预设账户或假登录，也不会发送任何外部消息。

环境变量：

| 变量                   | 用途                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| `PORT`                 | 监听端口，默认3000                                                   |
| `HOST`                 | 默认127.0.0.1；对外部署时显式设置为0.0.0.0                           |
| `DATA_DIR`             | 持久化目录，默认仓库内忽略路径 `.data`                               |
| `COOKIE_SECURE=1`      | HTTPS部署时启用安全Cookie                                            |
| `SETUP_TOKEN`          | 部署前可设置初始化令牌，首次注册需填入此令牌；不用在前端代码中写凭证 |
| `ALLOW_REGISTRATION=1` | 允许多账户注册，仅用于受控环境；私人部署默认不设                     |

本项目没有Sites、托管公网地址或已配置的HTTPS反向代理。**当前交付的是可启动项目，尚未公开部署。** 自动跨设备保存需要稳定的服务器、HTTPS、持久磁盘和同一账户。仅本机运行时，通过JSON导出/导入手动跨设备恢复，不能把浏览器缓存描述为自动同步。

公开部署前设置初始化令牌及HTTPS安全Cookie、将反向代理指向应用端口、保存持久数据目录。账户数据库和备份含私人计划；不要放在静态资源目录。服务器仅暴露明确的静态文件列表，数据库不能经公开地址下载。管理者如需备份SQLite文件，应先停止服务再复制整个数据目录，或使用SQLite在线备份工具；不要只复制处于写入中的主数据库而漏掉WAL文件。

## 数据保存和同步

- 每个用户独立SQLite状态文档；密码scrypt加盐哈希，会话为HttpOnly / SameSite Strict Cookie；接口按当前会话确定用户，忽略外部用户ID。
- 首次读账户状态才初始化种子；重启、刷新、重新部署（保留DATA_DIR）均不覆盖已有记录。
- 应用外壳通过Service Worker缓存，可在曾加载过该站点的同一浏览器离线重新打开；私人API数据不进入公共资源缓存。前端按账户保存已知服务端版本、原始基线及最新待同步状态到持久缓存；多个离线操作合并为待同步最新快照。每次修改先落本机，再尝试同源服务端保存。正常自动同步、联网重试和手工重试都有状态提示。
- 乐观并发版本检测返回409；界面展示同一记录的本机/服务器差异，用户逐条选择。不同ID记录合并。不会静默覆盖。若合并后日程发生冲突，界面提示并需手工解决。
- 账户会话过期时保留待同步缓存，重新登录同账户后恢复。退出不会删除该账户本机缓存；共享电脑使用后应清理站点数据，清理前先同步/导出。
- 面试与重排建议和正式计划分离。确认时整个状态作为单次SQLite更新原子提交，取消不改正式计划；撤销只在接受后没有新的计划/任务变化时允许，避免覆写实际和历史。
- JSON包含schemaVersion、exportedAt、项目、任务、时间块、习惯、事件、容量预留、复盘、建议、日志、设置。结构校验、覆盖范围预览、确认、导入前备份下载依次完成；失败不会损坏当前状态。浏览器下载被拦截时请先手工导出并保管。

## 排程与使用

- 初始数据：六份报告共18h；旧数据10个可重命名2h任务共20h；方案与综述真实工时保持未知，显式占位预算分别6h、25h。项目总估时与任务估时分开；排程使用任务剩余工时，填写项目总工时后请分配到阶段。工时不是完成证据。
- 方案内部目标10月14日（对“15号之前”的保守、可改解释）；10月15日导师跟进；10月19日实验目标启动依赖手工确认。方案提交不会完成导师确认。
- 综述初稿建议节点21日、导师提交22日、修改与格式检查28日、29—30日投稿准备、31日用户投稿目标。导师反馈未知，依赖阶段时间块标为待确认，不能在依赖未通过时记录开始/完成。
- 3周各3次3h健身、1次3h组会容量预留和1整日休息。默认18个投递日、90家；每天75分钟弹性投递，休息日独立免除，未完成不累积、不翻倍。健身与默认晚餐的半小时相交显式提示，请在设置确认生活时段调整。
- 净容量 `min(个人上限, 作息内空闲 - 未确定预留 - 一次15%缓冲)`。餐饮、起床与个人生活、睡前个人生活、休息、固定事件和健身先占日历。每日上限默认6h、可调至7h，包含投递；时间块默认90分钟、最长120分钟，块间15分钟不算工时，每日最多3个重点成果。
- 实验执行日默认未选，19日之后每周两个候选工作日预留2h；选定实际执行日后生成锁定2h操作块并释放该周未用预留。实际开始/完成需导师确认。实验等待只有明确“可自由支配”才不占工作容量，监测等待不可并行。
- 未来重排保留历史、已完成、进行中/部分完成和锁定块；未排入预算在项目/建议中明确显示，可延期或延长规划。修改日期范围时，扩展部分按默认周日休息、周一/三/六健身、周四组会、周二/五实验候选规则生成**待确认预览**，不会在打开网页时自动延长两个月。
- 面试输入独立时长、准备窗口、默认240分钟准备、单程通勤。保护方案、实验、锁定、休息与睡眠；先腾弹性工作，尽量排入120分钟准备块并在面试前完成。冲突或容量不足不能直接接受，需明确修改输入、相关事件或投递免除/负荷。
- 结束今日批量记录具体成果、实际分钟、原因及备注，保存当时计划快照。根据原因可预览剩余估时、等待跟进、最小下一步和未来日程调整；确认才应用。
- 所有排程由透明规则完成，未接入收费大模型，未向导师、公司或期刊发送任何内容。
